Chapter 01 · Blueprint

Architecture with visible seams.

Talkivana is a repository-native production system: GitHub owns the orchestration and audit trail, specialized engines do bounded work, and YouTube receives only approved outputs.

System topology

Five layers, one controlled loop

The architecture deliberately separates decisions, generation, media work, publishing, and learning. That makes expensive stages retryable and keeps approval state independent from transient runner state.

CONTROLGitHubActions, Issues, labels, secrets
INTELLIGENCEGeminiDrafting and structured revision
PRODUCTIONMedia stackChatterbox, Pillow, FFmpeg
DELIVERYYouTubePrivate upload, schedule, analytics
MEMORYRepository dataManifests, tracker, guardrails

Components

What each piece owns

A component is allowed to make only the decisions inside its boundary. No text model can publish, no renderer can approve, and no analytics recommendation can bypass the owner.

A · ORCHESTRATOR

GitHub Actions

Runs scheduled and event-driven jobs, displays live stages, fans out media workers, stores artifacts, and resumes from workflow state.

B · HUMAN INTERFACE

GitHub Issues

Holds the proposal, review conversation, private preview links, commands, labels, and final approval history.

C · TEXT ENGINE

Gemini Flash Lite

Produces structured candidate lessons. Deterministic validation and German quality review sit between generation and approval.

D · AUDIO ENGINE

Chatterbox V3

Synthesizes fixed English and German voices from repository reference recordings. Voice fallbacks are disabled.

E · VISUAL ENGINE

Pillow + FFmpeg

Builds branded frames and thumbnails, then combines exact narration and visuals into final MP4 assets.

F · CHANNEL ADAPTER

YouTube APIs

Creates private videos, applies metadata and thumbnails, schedules approved assets, and returns analytics.

Sources of truth

The files that define reality

Instructions are versioned beside the code. A workflow run should be explainable from its configuration, guardrails, issue record, and upload manifest.

Trust boundaries

Where authority stops

The system is public-source but private-control. Code and documentation can be read by anyone; credentials, voice source files, approval authority, and channel access remain restricted.

PUBLIC & VERSIONED

Safe to inspect

  • Workflow definitions and application code
  • Configuration without credentials
  • Guardrails and operating instructions
  • Generated tracker summaries intended for the repository
PRIVATE & CONTROLLED

Never expose

  • OAuth client secret and refresh token
  • Gemini API key
  • Full voice reference recordings
  • Private preview URLs and unapproved full assets
Architectural invariant

Generation can be automatic. Public distribution cannot. A pack needs both owner-issued approvals, and every failure leaves the asset private or stops before upload.

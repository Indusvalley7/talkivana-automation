Recovery cookbook

Open the matching recipe

Retry the narrowest stage that can correct the defect. A broad rerun costs more time and increases the chance of duplicate external actions.

Content feels unnatural Text only
  1. Comment REVISE CONTENT: with concrete examples.
  2. Check the regenerated A/B arc, register, vocabulary links, and translations.
  3. Use APPROVE CONTENT only after the complete pack is teachable.
Voice is wrong, robotic, or missing Voice boundary
  1. Comment RETRY VOICE: and name the asset, speaker, line, and desired change.
  2. Verify fixed reference mapping; do not permit fallback voices.
  3. Listen to the regenerated exact preview before final approval.
Text or layout is wrong Visual boundary
  1. Comment RETRY VISUALS: with the slide or phrase.
  2. Confirm English remains above German and pronunciation stays visible but silent.
  3. Verify mobile legibility and synchronization.
Final assembly is incomplete Video boundary
  1. Use RETRY VIDEO: for missing segments, audio/video drift, or incorrect assembly.
  2. Preserve already approved content unless the defect reveals a content error.
  3. Review the entire rebuilt private video.
YouTube upload partially fails Resume safely
  1. Read the upload manifest before retrying.
  2. Reuse recorded YouTube IDs for completed assets.
  3. Upload only missing assets; never restart blindly.
  4. Keep everything private until all required files are present.
Thumbnail returns HTTP 429 Defer
  1. Do not repeatedly retry.
  2. Preserve the private video ID and mark thumbnail application deferred.
  3. Wait through the cooling window and protect the normal daily budget.
  4. Run a bounded backfill later without changing schedule or metadata.
Publication slot has passed Catch up
  1. After final approval, apply the five-minute API buffer.
  2. Space multiple missed assets by at least 30 minutes.
  3. Tag the run as catch-up so timing analysis excludes it.

Timing experiment

Learn slowly enough to trust it

Performance is compared at equal ages after publication. Shorts and long videos are scored separately because their distribution surfaces behave differently.

Days 1–30 · Explore broadly

Rotate formats through four separated seed slots and build a balanced baseline.

Days 31–60 · 70% evidence, 30% experiment

Use promising windows more often while preserving controlled exploration.

Day 61 onward · 85% evidence, 15% experiment

Exploit accumulated evidence but retain enough exploration to detect changing audience habits.

Measurement windows · 24 h and 7 d

The first window shows launch behavior; the second captures slower discovery. They are not “check once” deadlines.

First-response checklist

When a workflow turns red

Start from evidence instead of rerunning everything.

1. Open Actions → failed run → failed job
2. Read the first real error, not the final cascade
3. Open the pack Issue and note its current label
4. Check the upload manifest before any upload retry
5. Choose the narrow command or manual workflow
6. Verify the resulting private asset before approval
